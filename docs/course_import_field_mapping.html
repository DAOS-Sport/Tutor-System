課程匯入格式 — 完整欄位對照

交付對象：工程／維運。資料來源為 8 份讀者結構化萃取（已剔除空白佔位 test 來源）。凡程式碼未明確佐證者標「待確認」；Ragic 對應不明者標「⚠️ 未對應」。

一、匯入架構總覽

  • 資料流向：Ragic（舊系統，多 AP / 多表單）→ 新系統 PostgreSQL。Ragic 為人事（H01）、場館（H05）、家長（Z01）、學員（Z02）之權威來源，採「唯讀同步」政策（系統不寫 H01）。
  • 目前現況 = 登入懶載入（lazy-load），無批次匯入：家長以手機 / LINE UID（Z01 1006846）即時查 Z01/Z02；教練以 H01 同步。server/services/ragic.js、ragicAdmin.js 完全沒有課程購買匯入邏輯（grep 確認 1001458/1004109/group-class-regular/after-school-class/報名單號/堂數/到期 全部 0 命中）。
  • 規劃中的批次匯入：需從 Z02 兩張購買子表（常態團體班 1001458、課後班 1004109）循「報名單號」連到 /group-class-regular/24、/after-school-class/5 取真正堂數／到期 → 寫入 course_periods／admin_enrollments。此鏈目前未實作、來源表未文件化、未凍結。
  • Schema 真實來源：server/bootstrap/coreSchema.js 與 server/bootstrap/admin.js（兩者 ensureSchema() idempotent 建表 + ALTER ... IF NOT EXISTS）。db/migrations/001_initial_schema.sql 是「v2.0 完整藍圖」但只部分套用；002_admin_tables.sql 由 admin.js 主動執行已套用。
  • Ragic 凍結點：server/config/ragicSchema.js（凍結 Z01/Z02/H01/H05 主檔欄位；未凍結購買子表與連結表單）。docs/ragic_api.md 為對照手冊（若與凍結點不一致以凍結點為準）；docs/schema_field_reference.html 的「舊系統(Ragic)對應」欄為空白可編輯欄、整份未填。
  • 核心風險：雙帳本。後台簡化鏈 admin_enrollments（堂數 total_sessions/used_sessions）與正式期別鏈 course_periods（同名堂數欄）平行存在、未強制連動；且全系統「選槽不遞增 used_sessions」，已用堂數一律以 checkin_records COUNT 為準。

⚠️ 雙帳本警示（必讀）

  • 總堂數：course_periods.total_sessions（第一真相）vs admin_enrollments.total_sessions（fallback，對帳前常 NULL）。
  • 已用堂數：course_periods.used_sessions 與 admin_enrollments.used_sessions 兩個計數器都不被遞增；LIFF /mine、/:id 改以 checkin_records COUNT 計，/lessons 卻直接 SELECT stored 欄位 → 同一期別在不同頁可能顯示不同已用/剩餘堂數。
  • 匯入準則：兩表 total_sessions 必須一致；若只填 used_sessions 欄位而無 checkin_records，LIFF「已用」會顯示 0。
  • 到期：只有 course_periods.expires_at（DATE NOT NULL），admin_enrollments 無到期欄；對帳建 period 前家長端看不到到期。
