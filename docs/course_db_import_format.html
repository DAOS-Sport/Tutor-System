本系統資料庫格式（匯入準備）— 家長／學員／報名課程流程

資料來源為 Ragic 舊系統（家長 Z01 /RAGIC_FORM_Z01、學員 Z02 /xinsheng/general-information/11）→ 新系統 PostgreSQL，採「唯讀同步」政策。目前無批次匯入，僅登入懶載入：家長以手機／LINE UID 即時查 Z01/Z02 落地。Schema 真實來源為 server/bootstrap/coreSchema.js 與 server/bootstrap/admin.js（idempotent 建表 + ALTER ... IF NOT EXISTS），db/migrations/001_initial_schema.sql 為藍圖但僅部分套用（bootstrap 只跑 coreSchema.bootstrap 與 admin.js(002)，不跑 001）。整條鏈最大風險為雙帳本（admin_enrollments 簡化鏈 vs course_periods 正式期別鏈）與選槽不遞增 used_sessions（已用堂數一律以 checkin_records COUNT 為準）。

0.3 匯入關鍵注意（格式約束 + enum 合法值 + 已知地雷）

  • 格式約束：phone → 09xxxxxxxx（去空白/連字號、全形→半形、+886→0）；id_number（身分證）→ ^[A-Z][0-9]{9}$ 大寫；birth_date 民國 Ry/MM/dd 轉西元（⚠️ ragic.js:422 正則有 \d 雙轉義 bug，匯入前自行轉好西元再灌）；transfer_last_5 → ^\d{5}$；invoice_number → ^[A-Z]{2}\d{8}$；venue_id 為場館代碼（如 B/C/X）。
  • enum 合法值（給錯會寫不進去或語意錯）：
  • course_type：1~6（1對1 … 1對6）
  • course_periods.status（真 ENUM）：pending_payment/payment_anomaly/active/completed/refunded
  • course_period_enrollments.status：active/transferred_out
  • course_sessions.status：pending_group_confirm/confirmed/completed/cancelled_normal/cancelled_penalty
  • coach_availability_slots.status：available/pending_group_confirm/booked/blocked
  • admin_enrollments.status（TEXT，無 CHECK，但請守值）：pending_payment/confirmed/active/cancelled/refunded
  • 雙帳本必一致：同一筆購買同時存在 admin_enrollments.total_sessions（帳本A）與 course_periods.total_sessions（帳本B＝對外真相），匯入時兩者數值必須相等，否則 LIFF 各頁顯示打架。
  • 已用堂數別只填數字：used_sessions 是「死欄位」，選槽/簽到都不會 +1；LIFF 的「已用/剩餘」一律用 checkin_records 的 COUNT 算。要呈現歷史已上堂數，必須補對應的 checkin_records 列，光填 used_sessions 不會顯示。
  • 到期只在 course_periods.expires_at（DATE NOT NULL）；admin_enrollments 沒有到期欄。匯入務必帶真實到期，勿用 NOW()+365 預設讓過期方案復活。
  • admin_enrollments 缺 ragic_record_id：PK 是內部 CP####，無法對應 Ragic 報名單號（1001451/1004095）。要可重跑匯入，建議先 ALTER TABLE admin_enrollments ADD COLUMN ragic_record_id 並建唯一索引，以報名單號當冪等鍵。
  • 目前沒有任何「課程購買」批次匯入程式（ragic.js/ragicAdmin.js 對購買子表 0 命中），這條鏈要自己寫；家長/學員可複用登入懶載入的 upsertLocalParent/upsertLocalStudents 語意以「匯入列＝登入會產生的列」收斂。
  • 學員 primary_venue_id 落不了地：students 表沒有此欄，Ragic Z02 1002175 館別匯入時無處可存（缺口）。
  • 緊急聯絡人（Z02 子表 1001170）新系統無表：要匯入需先新建 emergency_contacts。

雙帳本 / 缺口（必讀）

  • 總堂數須一致：course_periods.total_sessions（第一真相）vs admin_enrollments.total_sessions（fallback，對帳前常 NULL）；匯入時兩者必須一致。
  • used_sessions 死欄位：course_periods.used_sessions 與 admin_enrollments.used_sessions 兩套計數器，選槽/簽到都不 +1；已用堂數一律以 checkin_records COUNT 為準（cron 統計）。reconcile 設 0、revive -1（針對 admin_enrollments）、cancelSession(normal) -1（針對 course_periods）。若只填 used_sessions 而無 checkin_records，LIFF「已用」顯示 0。
  • 到期欄不對稱：只有 course_periods.expires_at（DATE NOT NULL）；admin_enrollments 無到期欄，對帳建 period 前家長端看不到到期。
  • admin_enrollments 缺 ragic_record_id：id 用內部 CP#### 而非 Ragic record_id → 無冪等對應 Ragic 報名單號（1001451/1004095），規劃匯入須新增 ragic_record_id 欄並以報名單號作自然鍵，否則重跑撞 PK 或重複建單。
  • approve 不建 period：核准只建 admin_enrollments(pending_payment)，真正 course_periods+course_period_enrollments 落地在對帳 ensureGroupCoursePeriod（需該期全員 confirmed + 團有 coach_id）。
  • revive 的 period_id 指向 admin_enrollments.id（非 course_periods.id）；admin_today_sessions/admin_cancelled_sessions 為後台獨立 mock 表，與正式 course_sessions/course_periods 無 FK 連動。
  • solo 學員 get-or-create 以 (parent_id, name) check-then-insert，無 DB 唯一鍵，並發或同名可能重複建學員。
  • 001-only 幻欄（全新 coreSchema 庫不存在）：parents.last_synced_at（parents.js:174 會引用未建欄位）、checkin_records.checked_in_by_student_id（coreSchema 不建，僅對既有 001 庫做 DROP NOT NULL）；皆僅存在於未被 bootstrap 執行的 001_initial_schema.sql。
