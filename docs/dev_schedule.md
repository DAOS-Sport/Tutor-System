# 個家教課程系統 — 開發優先順序排程
**版本：** v1.0 | **日期：** 2026-04-29  
**依據：** 需求架構書 v7.0 + Schema v2.0  
**建置平台：** Replit | **技術棧：** Node.js + PostgreSQL + React + LINE LIFF

---

## 排程總覽

| Phase | 名稱 | 週數 | 累計週 | 核心交付 |
|---|---|---|---|---|
| 0 | 環境建置與基礎工程 | 1.5W | 1.5W | DB、API 骨架、LINE 驗證 |
| 1 | 核心購課流程 | 3W | 4.5W | 報名、對帳、開通 |
| 2 | 排課與簽到 | 2.5W | 7W | 教練開槽、學員選槽、簽到 |
| 3 | 後台管理基礎 | 2W | 9W | 櫃檯、主管、對帳、堂數 |
| 4 | 聊天室 | 2W | 11W | WebSocket、多媒體、關鍵字警示 |
| 5 | 學習歷程 | 2.5W | 13.5W | 課前規劃、授課記錄、標籤、評鑑 |

## Phase 0：環境建置與基礎工程
**工期：1.5 週**  
**目標：所有後續 Phase 的地基，此 Phase 完成前不開始 Phase 1。**

### 0-1 Replit 專案結構初始化

```
/server         Node.js + Express API Server
/client/liff    React LIFF App（學員、教練端）
/client/admin   React Web App（後台）
/db/migrations  SQL Migration 檔案
/cron           定時任務
```

### 0-2 資料庫建置

- 執行 Schema v2.0 完整 SQL（31 張資料表、4 個 View）
- 新增 `coach_availability_slots`（v7 新增）
- 修改 `course_sessions`（新增 `availability_slot_id` FK，移除 `pending_coach`）
- 建立 migration 管理機制（使用 `node-pg-migrate` 或手動版本管理）
- 插入系統預設參數（`system_settings` seed）
- 插入預設關鍵字清單 seed
- 插入授課記錄預設標籤 seed

### 0-3 LINE 整合基礎

- 建立 LINE Login Channel（共用，所有場館）
- 建立 LIFF App（帶 venue 參數）
- 實作 LINE Login → 取得 UID
- 實作身分驗證 middleware（角色判斷：家長 / 教練 / 後台員工）
- JWT Session 管理

### 0-4 Ragic API 封裝模組

- 封裝 Ragic HTTP Client（含重試、錯誤處理）
- 實作 H01 教練在職查詢（過濾條件）
- 實作 H05 場館清單查詢（過濾條件）
- 實作 Z01 家長資料讀取
- 實作 Z02 學員資料讀取
- 雙向同步邏輯（本地 ↔ Ragic，含衝突處理）

### 0-5 基礎 UI 框架

- 套用品牌色系（`#15316a` / `#31aeab` / `#97bf36`）
- LIFF 共用 Layout、Header、Loading 元件
- 後台共用 Layout、Sidebar、Header 元件
- 錯誤頁面、Empty State 元件

### 0-6 LINE Flex Message 基礎模組

- 封裝 LINE Messaging API Client（各場館 Token 管理）
- 建立 Flex Message 模板引擎（品牌色套用）
- 實作推播發送 Queue（避免 rate limit）

**Phase 0 驗收標準：**
- [ ] DB 所有資料表建立完成
- [ ] LINE Login 可成功取得 UID
- [ ] Ragic API 可成功讀取教練、場館、學員資料
- [ ] 後台可用帳號密碼登入
- [ ] 可發送一則測試 Flex Message

## Phase 1：核心購課流程
**工期：3 週**  
**目標：學員完成從「瀏覽課程介紹」到「課程開通」的完整購課路徑。**  
**完成後可對行政與主管示範購課閉環。**

### 1-1 課程介紹頁（F-S01）

- LIFF 首頁課程介紹頁（未登入可瀏覽）
- 顯示各組別（1v1 / 1v2 / 1v3）說明、費用、堂數、有效期
- 資深教練識別標示（金色徽章）
- 後台管理介面：主管/管理員可編輯課程介紹內容（rich text + 圖片）
- 系統參數連動：費用、堂數自動帶入設定值

### 1-2 教練列表與選擇

- 顯示在職教練列表（即時打 Ragic H01）
- 一般教練 vs. 資深教練視覺區隔
- 顯示教練專長、個人介紹、修課係數後費用
- 選定場館（帶入 venue 參數）後過濾該場館可授課教練（預設全館）

### 1-3 課程報名流程（F-S02）

- 選組別 → 費用計算（原始 × 係數 × 優惠折扣）
- 1對多：輸入同組家長手機 → 列出學員 → 選擇正確學員
- 顯示場館銀行帳號 + **一鍵複製帳號按鈕**
- 填入轉帳末5碼 → 送出報名
- 建立 `course_period`（status = pending_payment）
- 建立 `course_period_enrollments`
- 建立 `payment_audit_logs`（action = transfer_submitted）
- 發送 Flex Message：報名成功通知

### 1-4 對帳流程（F-M02）

- 主管後台：待對帳清單（含最後一筆對帳操作記錄）
- 核對末5碼 → 確認 → 課程立即開通（status = active）
- 標記異常 → 填入異常說明
- 每次操作寫入 `payment_audit_logs`
- 確認後發送 Flex Message：課程已開通，引導選課時間

### 1-5 學員帳號與多學員管理

- 首次登入流程（UID 綁定 + 手機驗證）
- 新用戶自行註冊（填寫家長 + 學員資料，同步回寫 Ragic）
- 家長帳號下的學員切換

**Phase 1 驗收標準：**
- [ ] 家長可完整走過報名 → 填末5碼 → 送出的流程
- [ ] 主管後台可看到待對帳清單
- [ ] 確認對帳後課程狀態自動改為 active
- [ ] 報名成功與課程開通的 Flex Message 正確送出
- [ ] 1對多報名時可選取正確學員

## Phase 2：排課與簽到
**工期：2.5 週**  
**目標：教練開設槽位，學員選槽，完成簽到閉環。**  
**這是系統日常最高頻使用的功能，優先級最高。**

### 2-1 教練排課總表（F-C02）★ v7 核心

- 週視圖：顯示當週所有槽位（available / booked / blocked）
- 月視圖：色塊顯示每天槽位概況
- 新增槽位：選場館、日期時間、時長 → 送出 → 即時衝突偵測
- 封鎖槽位：available → blocked
- 解除封鎖：blocked → available
- 刪除槽位：僅限 available
- 批量新增：設定起迄日、週幾、時段、場館 → 一次建立（跳過衝突，顯示結果）
- 場館篩選器（多選）

### 2-2 衝突偵測 API

```
POST /api/availability-slots
→ 驗證：該教練是否在相同時間區間有既有槽位（available / booked）
→ 通過：建立槽位
→ 拒絕：回傳衝突詳情（哪個場館、幾點）
```

### 2-3 學員選槽流程（F-S03）★ v7 核心

- 課程開通後顯示「選擇上課時間」入口
- 日曆視圖：顯示教練在對應場館的 available 槽位
- 選取槽位

**1v1 路徑：**
- 選槽 → 即時建立 course_session（confirmed）
- 槽位改為 booked
- 發送 Flex Message：選槽成功確認

**1vN 路徑：**
- 選槽 → 槽位改為 pending_group_confirm（暫時鎖定）
- 發送 Flex Message 給同組其他家長（含同意/不同意按鈕）
- B 同意 → confirmed；B 拒絕 → 槽位釋回 available，通知 A
- Node-cron：每分鐘掃描 pending_group_confirm 超過 60 分鐘的槽位 → 自動 confirmed

### 2-4 教練本週課表（F-C01 / F-C02 整合）

- 教練端主頁：本週已確認課程一覽
- 篩選：場館、週幾
- 每筆時段點擊展開：學員姓名、課程期資訊

### 2-5 線上簽到（F-S04）

- 學員進入當日課程時段 → 點擊「簽到」
- 建立 `checkin_records`
- 同期同組學員：自動建立連動記錄（is_auto_linked = true）
- 顯示簽到結果畫面（含學員姓名、課程、時間）供櫃檯查驗
- 已使用堂數 +1（`used_sessions`）
- 教練端可查看當堂簽到記錄

### 2-6 自助取消課程（F-S05）

- 學員進入課程時段 → 取消
- 判斷距上課時間：> 24 小時 → 歸堂 + 槽位釋回；≤ 24 小時 → 扣堂 + 槽位釋回
- 課程時段 status → cancelled_normal 或 cancelled_penalty
- 對應槽位 status → available
- 發送 Flex Message 通知教練（含取消類型說明）

**Phase 2 驗收標準：**
- [ ] 教練可在週視圖新增/封鎖/刪除槽位
- [ ] 批量新增功能可正確建立多個槽位（跳過衝突）
- [ ] 學員可在日曆視圖看到 available 槽位
- [ ] 1v1 選槽後即時確認（無需等待）
- [ ] 1vN 選槽後同組確認流程正確執行（含 1 小時逾時自動確認）
- [ ] 學員簽到後顯示結果畫面，同組連動正確
- [ ] 自助取消後槽位正確釋回

## Phase 3：後台管理基礎
**工期：2 週**  
**目標：行政櫃檯與場館主管可操作日常管理工作。**

### 3-1 員工帳號管理（F-A02）

- 系統管理員：從 Ragic H01 拉取員工名單
- 指派角色（主管 / 行政櫃檯）
- 設定教練修課係數（100%～150%）
- 設定資深教練開關
- 產生後台帳號

### 3-2 場館設定（F-A03）

- 同步 Ragic H05 場館清單
- 各場館 LINE Messaging API Token 維護
- venue 參數對應設定

### 3-3 系統參數設定（F-A01）

- 後台介面：調整所有 system_settings 值
- 即時生效（不需重啟）

### 3-4 今日課表總覽（F-R01）

- 行政後台：今日所有 confirmed 課程時段
- 顯示：時間、場館、教練、學員、簽到狀態

### 3-5 報名管理（F-R02）

- 查看所有課程期報名狀態
- 搜尋：學員姓名、教練姓名、場館、狀態
- 付款對帳歷史查看

### 3-6 查驗學員簽到（F-R03）

- 核對學員出示的簽到畫面
- 掃描 QR Code 或手動確認（視設計決定）

### 3-7 堂數復活（F-M05）

- 主管後台：選取已取消課程時段 → 恢復已扣堂數
- 操作留存記錄（`payment_audit_logs` 或獨立 log）

### 3-8 退課操作（F-R04）

- 選課程期 → 填退課原因
- 自動計算退款金額（`final_price × 剩餘比例 × (1 - 手續費率)`）
- 顯示退款金額確認 → 執行
- 建立 `refund_records`
- 課程期 status → refunded

**Phase 3 驗收標準：**
- [ ] 後台角色指派、教練係數設定正常
- [ ] 今日課表總覽顯示正確
- [ ] 報名管理可搜尋、查看對帳歷史
- [ ] 堂數復活操作正確
- [ ] 退課操作計算金額正確

## Phase 4：聊天室
**工期：2 週**  
**目標：師生溝通全在系統內，防止私下流失。**

### 4-1 聊天室建立邏輯

- 課程期開通（status = active）時自動建立 `chat_rooms`
- 聊天室對應課程期（UNIQUE）

### 4-2 即時訊息（WebSocket）

- 後端：ws 或 socket.io 實作 WebSocket Server
- 前端：LIFF 與後台均接入 WebSocket
- 訊息即時推送、已讀/未讀狀態

### 4-3 多媒體訊息

- 圖片上傳 → Replit Object Storage → 顯示縮圖 + 點擊放大
- 語音錄製 → 上傳 → 播放條
- 影片上傳 → 縮圖播放
- 檔案上傳 → 顯示檔名與大小

### 4-4 關鍵字警示系統

- 每則訊息儲存時後端即時掃描 `keyword_list`
- 觸發 → 建立 `keyword_alerts`
- 發送 Flex Message 給場館主管：「[教練] 與 [家長] 的對話觸發警示關鍵字」
- 主管後台：警示清單查閱 → 標記處理結果

### 4-5 後台聊天記錄查閱

- 後台依課程期搜尋聊天室
- 唯讀瀏覽完整對話記錄
- 關鍵字警示記錄查看

### 4-6 關鍵字清單管理（F-A07）

- 管理員可新增、刪除、啟用/停用關鍵字

**Phase 4 驗收標準：**
- [ ] 訊息即時收發（WebSocket 正常）
- [ ] 圖片/語音/影片/檔案均可正常上傳與顯示
- [ ] 關鍵字觸發後主管收到 Flex Message 通知
- [ ] 後台可查閱聊天記錄

## Phase 5：學習歷程模組
**工期：2.5 週**  
**目標：資深教練加值服務上線，差異化競爭核心。**

### 5-1 教練特色專區（F-S01 補充 + F-C06）

- LIFF 課程介紹頁中的資深教練獨立專區（金色主題）
- 教練端：編輯個人介紹（富文字）+ 圖片上傳（多張排序）
- 主管可審核是否發布

### 5-2 課前規劃（F-C04 / F-S06）

- 教練端：新增/編輯課前規劃（草稿 → 發布）
- 欄位：課程目標、預期成果、學習規劃、初始評估、注意事項（富文字編輯器）
- 發布時發送 Flex Message 通知家長
- 家長端：查閱課前規劃

### 5-3 授課記錄（F-C05 / F-S06）

- 教練端：每堂課後進入授課記錄填寫介面
- **標籤快速輸入**：點擊標籤 → 自動生成文案 → 可微調
- **複製前一堂**：一鍵載入上一堂記錄所有文字欄位
- **媒體附件**：圖片/影片上傳（Replit Object Storage）
- 暫存 → 送出 → 家長可查看
- 送出後修改：保留版本歷史（`session_record_versions`）
- 送出時發送 Flex Message 通知家長

### 5-4 標籤庫管理（F-A08）

- 管理員後台：新增/編輯/分類系統預設標籤
- 教練個人標籤：教練端可自訂個人常用標籤

### 5-5 學習歷程總覽（家長端）

- 依課程期顯示：課前規劃 + 各堂授課記錄列表
- 可匯出完整學習歷程（PDF 或頁面列印）

### 5-6 期末評鑑（F-S12 / F-M09）

- Node-cron：最後一堂課簽到當天觸發評鑑邀請
- 發送 Flex Message 邀請家長填寫
- 7 天後若未填，發送一次提醒（`reminder_sent_at`）
- 家長端：4 維度星星評分 + 文字 + 續課意願
- 主管後台：教練考核報表（平均分 / 趨勢 / 文字回饋）
- 考核門檻設定（F-A09）

**Phase 5 驗收標準：**
- [ ] 資深教練特色專區可正確展示（含圖片）
- [ ] 課前規劃可草稿/發布，家長端可查閱
- [ ] 授課記錄標籤點擊後正確生成文案
- [ ] 複製前一堂功能正常
- [ ] 媒體附件可上傳與顯示
- [ ] 版本歷史正確儲存
- [ ] 期末評鑑邀請在最後一堂當天正確發送
- [ ] 主管考核報表顯示正確平均分

## Phase 6：優惠活動 + MGM 裂變推薦
**工期：2 週**  
**目標：行銷增長引擎上線。**

### 6-1 優惠活動 CRUD（F-M07 / F-A05）

- 主管/管理員後台：建立/編輯/停用優惠活動
- 欄位：名稱、類型（折數/固定折抵/折價券）、折扣值、門檻、適用組別（INTEGER[]）、場館、起迄日
- 折價券代碼產生（隨機或自訂）

### 6-2 購課介面優惠套用（F-S02 補充）

- 購課時自動比對符合條件的優惠（場館、組別、起迄日、購買期數）
- 顯示：原始費用 → 優惠說明 → 折扣後費用
- 折價券入口：手動輸入代碼 → 即時驗證 → 顯示折抵
- 建立 `promotion_usages`（資料隔離）

### 6-3 優惠活動查閱（F-R05）

- 行政後台：查看進行中優惠活動（唯讀，供推銷參考）

### 6-4 MGM 推薦連結（F-S10）

- 家長端：選擇要推薦的教練 → 產生專屬推薦連結（含推薦人 + 教練 ID）
- 分享按鈕（複製連結 / LINE 分享）
- 建立 `referral_records`

### 6-5 新客戶推薦流程

- 新客戶點開推薦連結 → 引導完成系統註冊
- 自動載入體驗課購買頁（5 折優惠自動套用）
- 體驗課付款 → 對帳確認 → 體驗課開通
- 體驗課簽到當天：發送 Flex Message 提供 9 折正期優惠

### 6-6 推薦方獎勵發放

- 體驗課對帳確認後：
  - 建立推薦方 9 折優惠券（promotions + 綁定 parent_id）
  - 更新 `referral_records.status = reward_issued`
  - 發送 Flex Message 通知推薦方

### 6-7 防刷機制

- 同一手機只能被推薦一次（referee_phone UNIQUE 於同教練）
- 推薦方不可自我推薦
- 體驗課必須完成簽到才觸發獎勵

### 6-8 MGM 統計報表（F-M10）

## Phase 8：整合測試與上線
**工期：1.5 週**

### 8-1 端到端 (E2E) 測試

以下為必測完整路徑：

**路徑 A（核心購課）：** 家長報名 → 填末5碼 → 主管對帳 → 課程開通 → Flex 通知  
**路徑 B（排課選槽）：** 教練開槽 → 學員選槽（1v1 即時）→ 簽到 → 堂數扣除  
**路徑 C（1vN 選槽）：** A 選槽 → B 收到確認邀請 → 同意/逾時 → 確認  
**路徑 D（自助取消）：** 取消（24 小時前）→ 歸堂 + 槽位釋回 → 教練通知  
**路徑 E（優惠購課）：** 優惠活動 → 購課時自動套用 → 資料隔離驗證  
**路徑 F（MGM 完整）：** 推薦連結 → 新客戶註冊 → 體驗課 → 簽到 → 推薦方獎勵  
**路徑 G（學習歷程）：** 課前規劃發布 → 授課記錄填寫（含標籤）→ 家長查閱  
**路徑 H（轉讓）：** 申請轉讓 → 主管審核 → 轉入方開通

### 8-2 LINE 推播全項測試

逐一驗證全部 18 種 Flex Message 通知正確觸發與送達。

### 8-3 Ragic 同步壓力測試

- 模擬大量用戶同時進入（同時打 Ragic API）
- 確認 Ragic API 回應速度在可接受範圍
- 必要時加入本地快取層（Redis 或記憶體快取）

### 8-4 效能基線測試

- 核心 API 回應時間 < 500ms
- WebSocket 訊息延遲 < 200ms
- 圖片/媒體上傳成功率 > 99%

### 8-5 使用者接受測試（UAT）

建議由以下人員實際操作：
- 行政人員：購課對帳、今日課表、退課操作
- 主管：對帳確認、評鑑報表、關鍵字警示處理
- 測試教練：開槽、排課總表、授課記錄填寫
- 測試學員：選槽、簽到、聊天室

### 8-6 上線準備

- LINE Messaging API Channel 各場館設定完成
- Ragic API Key 正式環境確認
- Replit 正式環境部署
- 備份策略確認（DB 定期備份）

**Phase 8 驗收標準：**
- [ ] 所有 E2E 路徑 A～H 測試通過

## 開發優先順序決策依據

### 為何 Phase 2（排課/簽到）排在 Phase 3（後台）之前？

排課與簽到是**每日最高頻**操作，教練與學員天天使用，且是整個系統可運作的前提。後台管理功能（報名管理、堂數復活）雖然重要，但使用頻率和用戶數量遠低於前端。

### 為何 Phase 4（聊天室）排在 Phase 5（學習歷程）之前？

聊天室是**即時防流失**的關鍵功能，只要師生互動開始，就需要有系統內溝通管道。學習歷程是加值服務，可以後上。

### 哪些功能可以並行開發？

若有 2 人以上團隊，以下 Phase 可部分並行：

| 並行組合 | 條件 |
|---|---|
| Phase 1 後半 + Phase 0 補充 | 同一開發者可連續進行 |
| Phase 3 + Phase 4 前半 | 後台管理與聊天室後端獨立，可分工 |
| Phase 5 + Phase 6 前半 | 學習歷程與優惠活動資料模型獨立 |
| Phase 7 轉讓 + 報表 | 兩者資料來源不同，可分工 |
