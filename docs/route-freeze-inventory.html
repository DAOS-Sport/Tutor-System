§ 01

角色總覽

系統有兩個獨立前端，各自的角色體系不同。關鍵：coach 不是後台登入角色——它只是員工資料表 role 欄位的一個值，教練本人一律走 LIFF，永遠進不了 admin 後台（最外層 RequireAuth roles=['admin','manager','staff'] 會擋掉）。

admin
系統管理員 · 後台
  • 後台 33 頁全開
  • 唯一能碰 settings / staff / venues / 關鍵字 / 門檻 / Ragic 系統設定
  • 後端多數寫入的最終權限
manager
主管 · 後台
  • 後台 24 頁
  • 報表 / 退費 / 轉讓 / 優惠 / 考核可碰
  • 看不到 8 個 admin-only 系統設定頁
staff
行政櫃檯 · 後台
  • 後台 13 頁
  • 對帳 / 建檔 / 簽到 / 客戶資料
  • 復活頁唯讀（歸還鈕隱藏）
parent
家長 · LIFF
  • LINE 登入，12h JWT
  • 報名 / 團購 / 付款 / 轉讓 / 學習歷程
  • 每次請求即時查 is_active
coach
教練 · LIFF（非後台）
  • LINE OAuth，走 /coach-portal
  • 課表 / 簽到 / 課前規劃 / 授課記錄
  • JWT 不查 is_active（見風險）

§ 04

登入身分流向

三條登入分支，凍結時每個箭頭都要拍板。前端唯一附 JWT 處：api/client.js axios 攔截器；token 存單一 key daos.user，line_uid 去敏不落地。

家長 LINE-first

LIFF 開啟 → liff.init → POST /auth/parent-line-login(id_token)
   ├─ logged_in            → 首頁 /
   ├─ need_phone_binding    → POST /auth/parent-bind-phone
   │      ├─ bound_and_logged_in → 首頁
   │      ├─ need_registration    → /register → POST /auth/parent-register-line
   │      └─ need_claim_verify    → 認領表單(學員姓名 + 登記手機 + 家長姓名) # 雙因子
   └─ token 失效           → liff.login 刷一次 or 顯示手機輸入

教練 OAuth · 現役

路徑含 /coach → 略過 LIFF SDK → RequireCoach 導 /coach-portal
   ├─ 有 30 天 portalToken → GET /coach-portal/session → /coach
   └─ 點「LINE 登入」→ GET /coach-portal/auth/line → LINE 授權 → callback
        ├─ lineLogin=existing → POST /auth/exchange(code)      # A 層:UID 已綁 → /coach
        └─ lineLogin=new      → POST /link-by-name(姓名)       # B 層:單因子·R1 劫持點 → /coach

殭屍：舊 /coaches/by-line-uid、by-phone 直登 — 前端已停用、後端仍活

後台 帳密

/login → POST /admin/auth/login → JWT{role, venue_ids} 存 localStorage
   → RequireAuth roles=['admin','manager','staff'] # coach 一律擋掉
   → 各頁 RequireAuth roles=[...] 疊加限制  ·  後端 requireAdminRole + venue scope
§ 05

風險清單

依嚴重度排序。🔴 為我逐行複核、確認可實際執行的攻擊；🟡 為越權/完整性/不一致；🟢 為低風險或需設計確認。每項附 file:line 與修法方向。

R1🔴 高教練帳號可被姓名單因子劫持
server/routes/coachPortal.js:240-326

任何人用自己的 LINE 跑完 OAuth，送一個「還沒登入過的在職教練姓名」即可綁成該教練、拿到 12h JWT + 30 天 token。教練姓名可從公開免登入的 GET /api/coaches 直接撈。剛上線 / 新進 / 換手機沒重登（line_uid 為 NULL）全中。綁到後能讀寫課表、學生與家長姓名電話、授課記錄。對比家長端認領要姓名+手機雙因子，此處只用姓名。成功綁定不發告警，只有 console.log。

修法：加第二因子（手機末碼 / 員工編號）或改「產生待審核請求 → 管理員/教練手機二次確認」；補「綁定成功」即時告警。
R2🔴 高家長能看到同班別家孩子的學習歷程
server/routes/learn.js:140-158 · server/services/learning.js:345-352

guard 只驗「這家長在此期別有學生」，通過後 listLearningHistory(periodId) 把該期別所有學生的 session_records（姓名、評語、作業）整包回傳，未依家長自己的孩子過濾。1對2/1對3 共班就互看。同專案 courses.js /mine 已示範正確 parent_id 過濾——此條是唯一漏掉的。

修法：在 service 帶入 parent 的子女姓名清單，過濾 student_records 只回本家的孩子。
R3🟡 中TRIAL50 體驗券可併發雙重折抵
server/routes/enrollments.js:155-169, 243-248

referral 狀態檢查未上 FOR UPDATE；markTrialPaid 更新 0 列被靜默忽略、不回滾；promotion_usages 也無 (promotion_id, parent_id) 唯一鍵。腳本併發兩次可拿兩份 5 折。

修法：referral 列上 FOR UPDATE；檢查 markTrialPaid rowCount，0 則回滾；加唯一鍵。
R4🟡 中已停用課程組別可繞過報名下單
server/routes/enrollments.js:78-86

讀 base_price 只檢查 > 0，未過濾 is_active；但團購 groupOrders.js:455-463 有擋。後台停用組別後直接打 POST /enrollments 帶該 course_type 仍能成單。兩條路徑邏輯已漂移。

修法：enrollments 讀價一併過濾 is_active，與團購對齊。
R5🟡 中場館範圍（Task #90）落實不徹底 — manager/staff 可跨館
mgmStats.js · staff.js:323 · promotions.js:112 · learn.js:110-182 · ragicZ03.js（全檔）

這些端點未接 getScopedVenueIds/isVenueInScope，可帶任意 venueId 撈別館資料：MGM 轉換率(R7a)、教練名單/手機(R5)、建別館優惠券(R7b)、教練考核/自介(R7)、Z03 可改任意館(R7c)。同系統 transfers/reports/enrollments 卻做得完整——代表 scope 是「按模組自己決定要不要接」。

修法：逐一補 scope；coach-eval / ragicZ03 若屬總部集中審，改為書面豁免+檔頭註記。
R5b🟡 中關鍵字警示 staff 可看，與註解矛盾
server/routes/admin/chat.js:157-158

註解白紙黑字「staff 不應看到關鍵字命中」，程式碼卻 requireAdminRole('admin','manager','staff')。

修法：拍板 staff 能否看 → 改碼或改註解二選一。
R6🟡 中教練端兩套登入並存，舊的是殭屍
server/routes/coaches.js:100, 194

by-phone / by-line-uid 前端已停用、後端仍活可直接打，且不受新流程告警/衝突處理管轄。by-phone 還允許 id_token 放 query string（同檔 by-line-uid 卻只收 header 防外洩，自相矛盾）。

修法：下架這兩端點，只留 coach-portal；過渡期至少收斂 id_token 為 header-only。
R7🟡 中教練停權後 JWT 仍可用
server/middlewares/coachAuth.js:31-42

requireParent 每次查 parents.is_active，但 requireCoach 沒查 coaches.is_active。教練被下架後手上 12h JWT 仍能開時段、簽到、寫記錄。兩端失效速度不對等。

修法：requireCoach 補 is_active 即時查核，與 parentAuth 對齊。
R8🟡 中角色閘不一致 — 部分端點只掛 auth 不分角色
customerParents/Students（全 CRUD）· sessions.js:243,276（backfill/checkin）

staff 可讀+改家長/學員 PII（含 reveal 解遮罩，學員有 audit、家長沒有）；staff 可補打卡/建簽到。但同檔 /:id/revive 卻限 admin/manager——標準不一。

§ 07

凍結行動計畫

三個方案不是選一個，而是由淺到深疊上去。核心洞見：把「auth / 角色 / 場館」三件事從各檔自由心證，改成框架強制——這才是「寫死」的本體，其餘 IDOR/金流是必補的個案。

0

修 R1 教練姓名劫持、R2 學習歷程互看、R3 TRIAL50 併發、R4 停用組別繞過。都是明確補法、範圍小。

2
拍板 — 宣告式契約 + CI 守門 方案 C · 字面的「寫死」
建一份 route manifest（每條 route 明列 method/path/role/scope/公開），寫測試列舉 Express 實際註冊路由，對不上 manifest 就 CI 失敗。以後加 route 必須先登記，否則過不了。這份表本身就是你要的流向文件。已有 route-audit.js 可當底座擴充。
