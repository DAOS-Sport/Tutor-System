1 · 技術現況 vs 施工令前提（實測對照）

施工令多處以特定技術棧為前提。以下每一列都以實際指令／檔案佐證，因為這直接決定「三層鎖」能用什麼機制實作。

施工令假設實際現況（證據）影響
TypeScript 專案 純 CommonJS JS。find server -name '*.ts' = 0；全站 require()/module.exports 「少帶 scope = 編譯錯」字面上不可能——沒有編譯器、沒有型別層可在 build 期擋掉缺參數。
Drizzle ORM server/models/db.js 僅 10 行，匯出原生 { pool }（node-postgres）；node_modules 內無 drizzle-orm；63 檔用原生 pool.query 沒有 ORM 攔截點；ScopedRepository 必須從零打造，並手動遷移每個呼叫點。
ESLint 規則就緒（no-restricted-syntax 等） repo 內無任何 ESLint 設定檔，devDependencies 也沒有 A 層「禁裸掛」、C 層「禁 import raw db」需先從零架起 ESLint 才談得上自訂規則。
mount() / manifest / referee 已存在可改 三者皆不存在；218 條 router.<verb> 全為裸掛；admin 子路由經 admin.js 逐一 router.use 裁判、宣告表、強制掛載都是全新基礎建設，不是既有 seam 的重構。
統一的 scope 模型 全站無 tenant/org 欄位；唯一維度是 venue；students 無 venue 欄位（只能經 parents.primary_venue_id join）；家長/教練 JWT 不帶 venue scope 不是 {欄位:值}，得是 union：venue | predicate | public。單純的 scoped repo 不夠，必須支援 predicate 函式（chat 房成員、group-order by-token）。
單一「request 綁定」的 scope 主要 DB 寫入在 非 HTTP 路徑（cron、Ragic sync、websocket、fire-and-forget writeback），沒有 req，getScopedVenueIds(req) 叫不到 這些路徑今天以「全場館隱含權限」執行——正是 finding 1 破口（§6）。需明確登記 trusted-internal，而非硬套 scoped-repo。
測試框架就緒 無 jest/vitest；測試是自訂 node 腳本（tests/e2e/_lib.js + path_*.js，打真實 server） 負向 lint 測試、修前/修後測試都要沿用或擴充這套輕量 harness。

既有可用資產（好消息）：server/scripts/route-audit.js 可跑、產出 218 handler / 202 前端呼叫 / 8 個無前端 caller 的靜態稽核——這是漂移守門的現成底座；adminAuth.js 已有 getScopedVenueIds / isVenueInScope 手刻 venue 分域，是 C 層可承接的既有樣式。

3 · 核心決策點：強制機制選型（擋在關鍵路徑）

施工令要「少帶 scope = 編譯錯，runtime throw 不算數」。這在無編譯器的 JS 棧無法照字面實現。三個可行路線如下，須擇一（或組合）後才展開 §5 的結構性建置：

選項成本 / 風險能達成的保證
A · 全面遷移 TypeScript + Drizzle
（照字面實現施工令）		 很高 / 高風險
~63 資料檔＋全 routes/services 改 .ts、每表建 Drizzle schema、遷移所有原生 pool.query 與 pool.connect()/交易區塊。週級改寫、活金流系統大爆炸半徑。		 唯一能給字面編譯期保證（scope 設為必填型別參數 → 少帶即 tsc 錯）。
C + B · lint 規則 + 執行期 referee + 漂移測試，再疊 checkJs/JSDoc
建議		 中低 / 低風險，可增量
架 ESLint（no-raw-db-import / no-bare-mount）+ 執行期 referee（缺 scope 即 fail-closed throw，涵蓋非 HTTP 以 trusted-internal 登記）+ 擴充 route-audit 為漂移測試；再對 repo 邊界加 checkJs+JSDoc 靜態檢查。		 lint 期 + 執行期 + CI 三層擋掉「未分域查詢上線」「裸掛上線」；checkJs 對走 typed wrapper 的呼叫近似「缺參數即靜態錯」。非字面編譯錯，但達成同一安全結果。
C only · 最小護欄 最低 / 最快
同上但略去 checkJs/JSDoc 靜態層。		 lint + 執行期 + 漂移測試；不提供任何靜態型別近似。

建議：採 C+B，明確否決 A（或無限期延後）。理由：A 為滿足「編譯錯」而對活金流系統做週級重寫，是最高風險、最低邊際安全的路；C 以 lint+執行期+CI 交付施工令真正要的安全結果（不讓未分域 DB 存取／裸掛上線），B 再對 repo 邊界加上真實（雖部分）的靜態閘。這是本棧能做到的誠實上限。

6 · finding 1 破口面：非 HTTP DB 路徑（必須涵蓋）

這些路徑沒有 req，getScopedVenueIds() 叫不到，今天以「全場館隱含權限」執行——這是 finding 1 的實質破口。分三類處理：

  • Class A｜真·跨場館可信（登記 trusted-internal，勿硬套 scoped-repo）：
    • server/cron/index.js——全域排程，UPDATE course_sessions（自動確認）、coach_availability_slots、notification_log；venue_id 只用於推播路由、不約束列。
    • server/services/ragicAdmin.js——最大面（~46 pool + ~72 client query）。最高危：_pullParentsStudentsImpl 對 parents 全表掃描後 hardDeleteParentIfSafe——背景 job 的全域跨場館破壞性清除。
    • db/migrate.js——自帶 Pool、全 DDL，於 app auth 之外（ops 登記）。
  • Class B｜雙 caller（HTTP 登入/註冊 與 cron pull 都會叫）→ scope 須由 caller 注入，否則是 scope 洗白洞：services/parentSync.js、parentRefresh.js、ragicWriteback.js（在請求交易 commit 後才 fire-and-forget，per-request scope 已結束）。
  • Class C｜websocket（授權正確性，寫入破口低）：/ws chat（manager WS scope 取自 payload.venue_id 單值，比 HTTP 的 venue_ids[] 窄）、/ws/admin 簽到匯流排（零 DB，靠記憶體 adminVenueIds[] 過濾）。

結構限制：無 tenant/org 欄位；students 無 venue 欄位（join parents.primary_venue_id）；admin_enrollments 以 phone 字串連家長、以 name 陣列連學生（非 FK），只能用 venue_id 欄位分域。

D9 死碼候選（每筆刪除前須 grep 零 caller）：8 個無前端 caller 的 handler 中，coach-portal/auth/line/callback（LINE OAuth 外部呼叫）與 admin/periods/:id/activate（active⇔chat_room 不變式唯一即時維護者）為假陽性、勿刪；admin/coaches.js 整檔為 410 tombstone、auth/parent-login 與 line-config-debug 為 env-gated 遺跡——皆候選，須先 grep client+cron+scripts 證明零 caller。另：middlewares/auth.js 為死碼（零 importer）但一旦被接是 fail-open 危險（用 obsolete role model），建議移除或明確標記。
