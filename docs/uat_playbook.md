# UAT 使用者接受測試劇本

> 對象：客戶端 UAT 主持人 + 4 位測試者（行政、主管、教練、學員家長）
> 環境：UAT 環境網址、4 組測試帳號、測試 LINE 群組
> 通過標準：每個劇本步驟皆能完成且沒有 P1 問題

## 角色與帳號
| 角色 | LIFF / Admin | 帳號 | 預設密碼 |
|---|---|---|---|
| 行政 (staff) | Admin | `staff_uat` | `Daos@2026` |
| 主管 (manager) | Admin | `manager_uat` | `Daos@2026` |
| 教練 (coach) | LIFF（教練視角） | LINE 登入 + 後台帳號連動 | LINE 登入 |
| 學員家長 (parent) | LIFF | LINE 登入 | LINE 登入 |

> 上線前請務必：1) 改掉預設密碼；2) 把 UAT 帳號停用或刪除。

---

## 行政（staff）

### S-1 對帳
1. 登入 Admin → 對帳列表
2. 找一筆 pending 報名 → 輸入末 5 碼匹配 → 點「確認對帳」
3. 確認家長收到「課程開通」Flex（#2）
4. `admin_enrollment_audit_logs` 新增 1 筆

### S-2 今日課表 / 簽到
1. 進入「今日課表」
2. 找 1v1 session → 點「簽到」→ 確認 enrollment 剩餘堂數 -1

### S-3 退費 / 復活
1. 退費：找已開通 enrollment → 退費（必填理由 + 金額）→ 列表狀態變 `refunded`
2. 復活：點「復活」→ 狀態回 `active`，audit log 寫入

通過：3 個流程都看到 toast 成功提示，且資料庫狀態正確。

---

## 主管（manager）

### M-1 對帳結果覆核
1. 登入 → 對帳列表 → 確認 staff 經手紀錄一覽

### M-2 評鑑報表
1. 「評鑑報表」→ 選日期區間 + 場館 → 各教練平均分數 / 趨勢圖顯示

### M-3 關鍵字警示
1. （由教練 / 學員觸發後）→ 「警示」頁能看到當天觸發紀錄

### M-4 課程轉讓審核
1. 「課程轉讓」→ 待審 tab → 任選一筆 → 填審核備註 → 通過
2. 雙方家長收到「轉讓結果」Flex（#15）

通過：可獨立完成所有 manager-only 操作，且看到 audit / 推播。

---

## 教練（coach, LIFF）

### C-1 開放可上課時段
1. LIFF → 教練主頁 → 「我的時段」→ 拖曳 / 框選新時段（9:00–11:00）→ 儲存
2. 學員端可即時看到該時段（≤ 5s）

### C-2 排課總表
1. 「我的課表」→ 確認本週 sessions 列表

### C-3 課前規劃 / 授課記錄
1. 點任一 session → 「填課前規劃」→ 草稿存檔
2. 「發布」→ 家長收到 #10「課前規劃發布」
3. 「填授課記錄」→ 套用 ≥ 2 個標籤 + 文字 → 發布
4. 家長收到 #11「授課記錄送出」

### C-4 教練介紹送審
1. LIFF → 我的介紹 → 編輯 → 上傳新照片 → 送審
2. Admin 可在 CoachIntrosReviewPage 看到 pending

通過：全部步驟可在 LIFF 完成、無錯誤畫面。

---

## 學員家長（parent, LIFF）

### P-1 完整購課（路徑 A）
1. 進 LIFF → 課程介紹 → 報名 → 收 #1
2. 補末 5 碼 → 行政對帳 → 收 #2

### P-2 1vN 同組確認（路徑 C）
1. 學員 A 選 1vN 槽 → 學員 B 收到 #4
2. B 60 分內未回 → 自動 #5 確認

### P-3 自助取消（路徑 D）
1. 距開課 > 24h 取消 → 堂數歸還 + 教練收到 #8
2. < 24h 取消 → 顯示警告、扣堂

### P-4 課程轉讓（路徑 H）
1. 「我的課程」→ 申請轉讓 → 對方手機 + 堂數 → 提交
2. 主管審核（M-4）→ 收到 #15 結果

### P-5 學習歷程（路徑 G）
1. 「我的課程」→ 點任一課程 → 「學習歷程」
2. 顯示課前規劃 + 已發布授課記錄 timeline + 列印按鈕

### P-6 期末評鑑
1. 最後一堂簽到當天 → 收到 #12
2. 點按進入 → 4 維度 + 文字 + 是否續報 → 提交

### P-7 MGM 推薦（路徑 F）
1. 「我的推薦」→ 取得連結 / QR → 分享給新客戶
2. 新客戶報名體驗課 → 對帳通過 → 推薦人收到 #17
3. 體驗課當天 → 新客戶收到 #18

通過：以上 7 個 P 流程全部跑完無 P1 問題。

## P1 / P2 / P3 缺陷分級
- **P1**：阻擋 happy path（無法完成核心流程）→ 上線阻擋
- **P2**：功能可用但體驗有明顯問題（文案、版面）→ 上線後 1 週內修
- **P3**：nice-to-have / 邊緣案例 → 進入 follow-up 列表
