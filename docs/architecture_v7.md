## 一、系統概述

### 1.1 系統名稱
個家教課程系統

| 學員 / 家長 | LINE LIFF Web App | 透過各場館 LINE@ 官方帳號進入 |

## 六、教練可用時段系統（核心新架構）

### 6.1 設計理念

**v6 以前的問題：**  
學員主動申請時段 → 教練審核（確認/拒絕）→ 通知學員，每次排課最多需要三次訊息往返，雙方摩擦極高。

**v7 新設計：教練開槽，學員選槽**  
教練在系統中預先開放「可授課時段槽位」，學員只能從教練已開放的槽位中選擇，系統即時確認，完全不需要教練再次審核。

### 6.2 槽位狀態定義

| 狀態 | 說明 |
|---|---|
| `available` | 可預約（教練已開放，尚未被選取）|
| `booked` | 已預約（有對應 course_session，學員已選取）|
| `blocked` | 封鎖（教練手動設為不可用，如請假、有其他安排）|

### 6.3 教練開設槽位規則

- 每位教練可在任意場館、任意時段開設槽位
- 每個槽位包含：場館、日期、開始時間、課堂時長
- **同一教練同時段只能有一個槽位**（跨場館亦然）
- 排程衝突偵測在**教練新增槽位時**即時驗證
- 教練可手動「封鎖」已開放的空閒槽位（但不可封鎖已被預約的槽位）
- 「批量新增」功能：一次選取多個日期/週期，批量建立相同時段的槽位

### 6.4 排程衝突偵測（簡化版）

v6 以前，衝突偵測在學員「送出預約申請時」觸發。  
v7 改為在**教練「新增槽位時」**觸發，更早攔截，且只需做一次：

```
教練新增槽位時：
1. 查詢該教練所有狀態為 available / booked 的槽位
2. 若新槽位時間範圍（start_at ～ start_at + duration）與任一既有槽位重疊
   → 拒絕建立，顯示「此時段與 [場館名稱] 的課程時段衝突」
3. 通過驗證 → 建立槽位（狀態 = available）
```

### 6.5 學員選槽流程

```
【1 對 1 課程】
Step 1.  學員進入已開通課程期 → 點選「選擇上課時間」
Step 2.  系統顯示該教練所有 available 槽位（日曆視圖）
         → 場館：已在購課時選定，只顯示對應場館的槽位
Step 3.  學員選取槽位 → 確認
Step 4.  系統即時建立課程時段（status = confirmed）
Step 5.  槽位狀態改為 booked
Step 6.  Flex Message 通知：「課程時段已預約成功，[日期 HH:MM]」

【1 對 多 課程】
Step 1.  A 家長進入課程期 → 選取 available 槽位 → 確認
Step 2.  槽位暫時鎖定（status 標記 pending_group_confirm，保留 1 小時）
Step 3.  Flex Message 通知 B 家長：
         「A 家長已選取 YYYY/MM/DD HH:MM 的課程時段，請於 1 小時內確認
          ✅ 同意  ❌ 不同意」
Step 4a. B 確認同意 → 正式建立課程時段（confirmed），槽位改為 booked
Step 4b. B 選擇拒絕 → 填入原因 → 通知 A 家長，槽位釋回 available
Step 4c. 1 小時內未回應 → 系統視為同意，自動確認，槽位改為 booked
Step 5.  Flex Message 通知所有同組家長：「課程時段確認！[日期 HH:MM]」
```

### 6.6 教練排課總表介面（F-C02，全新功能）

教練端 LIFF 新增一個完整的「排課總表」頁面：

**週視圖：**
```
排課總表
篩選：[場館 ▼] [週 ◀ 04/28～05/04 ▶]

         週一  週二  週三  週四  週五  週六  週日
09:00    [B-可] [C-已]              [B-可]
10:00    [B-已]       [B-可]        [B-已]
11:00              [B-封]
14:00         [C-可]       [C-可]

圖例：可 = available（綠）  已 = booked（藍）  封 = blocked（灰）
```

**操作功能：**
- 點擊空白時段 → 新增槽位（選場館、確認時間、時長）
- 點擊 `available` 槽位 → 可封鎖或刪除
- 點擊 `booked` 槽位 → 查看預約學員資訊（唯讀）
- 點擊 `blocked` 槽位 → 可解除封鎖
- **批量新增**：選取多個日期（如「每週二、四 09:00，持續到 6/30」）→ 一次建立多個槽位

**月視圖（選填）：**
- 以月為單位查看整體授課規劃
- 色塊顯示每天的槽位狀況

## 七、資深教練體系

### 7.1 教練分級

| 層級 | 修課係數 | 學習歷程 | 期末評鑑 | MGM 推薦 |
|---|---|---|---|---|
| 一般教練 | 100% | 無 | 有 | 有 |

### 7.2 費用計算

```
基本費用 = 各組別定價
實際費用 = 基本費用 × 教練修課係數（100%～150%）
優惠後費用 = 實際費用 × 優惠折扣（若有符合）
```

### 7.3 購課介面識別
- 資深教練：金色徽章 + 「含學習歷程服務」標註 + 係數後費用
- 一般教練：無特殊標識

## 九、課程預約與選槽完整流程

### 9.1 購課完整流程

```
Step 1.  學員進入 LIFF → 選場館、選教練、選組別
Step 2.  若 1 對多：填入同組其他家長手機 → 選正確學員
Step 3.  系統顯示費用（原始 → 係數後 → 優惠後）
Step 4.  顯示場館銀行帳號 + 【一鍵複製帳號】
Step 5.  學員完成轉帳 → 填入末5碼 → 送出報名
Step 6.  狀態「待對帳」，Flex Message：報名成功，等待對帳確認
Step 7.  主管對帳確認 → 立即自動開通
Step 8.  Flex Message：課程已開通，引導至選擇上課時間
```

### 9.2 選槽完整流程（v7 新設計）

```
【購課完成，進入選槽】

Step 1.  學員進入已開通課程期 → 點選「選擇上課時間」
Step 2.  系統顯示教練在對應場館的所有 available 槽位
         介面形式：日曆視圖（可切換週/月）
         槽位狀態：available（可選，綠色）/ booked（已預約，灰色）
Step 3.  學員選取槽位

【1v1 課程】
Step 4.  確認選槽 → 系統即時建立課程時段（confirmed）
Step 5.  槽位狀態 → booked
Step 6.  Flex Message 通知學員/家長：
         「課程時段預約成功！
          教練：XXX · 場館：XXX · 時間：MM/DD HH:MM」

【1 對多課程】
Step 4.  A 家長確認選槽
Step 5.  槽位狀態暫改為 pending_group_confirm（暫時鎖定）
Step 6.  Flex Message 通知 B（及所有同組）家長：
         「A 家長已選取 MM/DD HH:MM 的課程時段，請於 1 小時內確認」
         [✅ 同意] [❌ 不同意]
Step 7a. B 同意 → 正式建立課程時段（confirmed）→ 通知所有組員
Step 7b. B 拒絕 → 填入原因 → 通知 A 家長，槽位釋回 available
Step 7c. 1 小時未回應 → 自動視為同意 → 正式建立，通知所有組員
```

### 9.3 與 v6 的主要差異對照

| 項目 | v6 舊設計 | v7 新設計 |
|---|---|---|
| 時段發起方 | 學員/家長 | 教練（事先開設槽位）|
| 教練需要審核嗎？ | 需要 | **不需要** |
| 排程衝突偵測時機 | 學員送出申請時 | 教練新增槽位時 |
| 1v1 確認時間 | 等教練審核（不確定）| **即時確認** |
| 1vN 確認時間 | 等同組 + 等教練 | 等同組（1小時逾時自動同意）|
| 移除的通知 | — | 時段申請通知、時段確認/拒絕通知 |
| 新增的通知 | — | 槽位選取即時確認通知 |

## 十、自助取消課程

### 10.1 規則

| 情況 | 條件 | 堂數處理 | 槽位處理 |
|---|---|---|---|
| 正常取消 | 距上課時間 > 24 小時 | 歸還 1 堂 | 槽位釋回 `available` |
| 逾時取消 | 距上課時間 ≤ 24 小時 | 扣堂，不歸還 | 槽位釋回 `available` |

### 10.2 流程

```
Step 1.  家長進入 LIFF → 找到課程時段 → 點選「取消本堂課」
Step 2.  系統顯示：距上課時間、取消結果（歸堂 or 扣堂）
Step 3.  確認取消
Step 4.  課程時段 status → cancelled_normal 或 cancelled_penalty
Step 5.  對應槽位 status → available（釋回，教練可再安排他人）
Step 6.  Flex Message 通知教練（含正常/逾時取消說明）
Step 7.  Flex Message 通知學員/家長確認取消
```

**1 對多取消：**  
任一學員家長取消 → 全組同步取消 → 槽位釋回 available → 通知所有組員家長與教練

## 十一、學習歷程功能模組（資深教練專屬）

### 11.1 課前規劃

教練在課程期開始後（或第一次選槽前後）建立本期學習規劃，發布後家長可查閱。

**欄位：** 課程目標 / 預期成果 / 學習規劃 / 初始程度評估 / 注意事項  
**狀態：** 草稿 → 已發布  
**修改：** 發布後教練仍可修改  
**觸發通知：** 首次發布時 Flex Message 通知家長

### 11.2 授課記錄

每堂課完成（簽到後）教練填寫，支援暫存 → 送出 → 送出後修改。

**欄位：** 上課內容摘要 / 學員表現評估 / 下堂課預備方向 / 課後練習作業 / 媒體附件（圖片/影片）/ 備註  
**低摩擦設計：**
- 標籤化快速輸入（點擊 → 自動生成文案）
- 載入前一堂記錄（一鍵複製，教練僅修改差異）
- 照片/影片附件上傳（Replit Object Storage）

**可見性：** 暫存時不可見 → 送出後家長可查閱 → 修改後即時更新  
**版本歷史：** 每次送出後修改均留存版本快照

### 11.3 課程期末評鑑

最後一堂課簽到當天，系統自動邀請家長填寫。

**評鑑格式：**
- 教學品質 / 溝通態度 / 學員進步 / 整體滿意度（各 1-5 星）
- 開放文字回饋（選填）
- 是否願意續課（是 / 否 / 考慮中）

**可見性：** 主管/管理員 → 完整明細；行政櫃檯 → 平均分；教練 → 自己的匿名平均分  
**考核應用：** 整體滿意度門檻（預設 ≥ 4.0）供主管決定是否維持資深教練資格

## 十二、聊天室功能模組

### 12.1 架構方案（B + C 組合）
- 全量訊息儲存，管理者主動依課程期查閱
- 關鍵字警示：觸發後 Flex Message 通知主管
- 使用者協議需告知：「本系統保留師生對話記錄供場館管理使用」

### 12.2 聊天對象
每個課程期對應一個獨立聊天室（UNIQUE），教練與家長在系統內溝通，防止私下加 LINE 導致場館客戶流失。

### 12.3 支援訊息類型
文字 / 圖片 / 語音 / 影片 / 檔案（Replit Object Storage）、WebSocket 即時通訊

### 12.4 關鍵字警示清單（管理員可調整）
- 私下聯繫：私下加 LINE、LINE ID、加我好友、私聊、另外約
- 私下金流：私下轉帳、直接匯款給我、不要透過系統
- 規避管理：不要讓主管知道、偷偷

## 十三、優惠活動系統

### 13.1 設計原則（資料隔離）
課程期僅記錄 `original_price`（原始費用）與 `final_price`（實際收費），優惠計算獨立存於 `PromotionUsage` 表，不污染課程資料。

### 13.2 優惠類型
- PERCENTAGE：折數（如 0.95 = 95 折）
- FIXED_AMOUNT：固定折抵金額
- COUPON_CODE：折價券代碼（學員手動輸入）

### 13.3 門檻類型
- PERIOD_COUNT：購買期數門檻（如 2 期以上）
- AMOUNT：消費金額門檻（預留擴充）

### 13.4 MGM 相關優惠（自動建立）
- 體驗課：新客戶專用，原價 50%，每人限用 1 次
- 新客戶正期：體驗課結束當天，正期 9 折
- 推薦方獎勵券：9 折，限 1 期，發放後 90 天有效

## 十四、MGM 裂變推薦機制

### 14.1 完整流程

```
推薦方：家長 → 選擇要推薦的教練 → 產生專屬推薦連結 → 分享給親友
被推薦方（新客戶）：點開連結 → 完成系統註冊 → 體驗課（5折，1堂）→ 付款
體驗課結束當天：Flex Message 通知 → 今日購買正期課程享 9 折
推薦方獎勵：體驗課對帳確認後 → 系統自動發放 9 折優惠券（限折抵 1 期，90 天有效）
```

### 14.2 防刷機制
- 同一手機號碼只能被推薦一次
- 同一 LINE UID 只能被推薦一次
- 推薦方不能推薦給自己
- 體驗課必須完成簽到才觸發推薦方獎勵

## 十五、課程轉讓機制（個別份額轉讓）

### 15.1 定義
學員將個人在某課程期中剩餘份額轉讓給另一位學員，同組其他人不受影響。

### 15.2 流程

```
Step 1.  學員申請轉讓 → 填入轉入方手機 → 選轉入學員
Step 2.  系統顯示摘要（剩餘堂數、有效期限、手續費 500 元）→ 送出
Step 3.  Flex Message 通知主管審核
Step 4.  主管審核通過 → 轉出方份額標記「已轉出」→ 建立轉入方新名冊

Step 6.  未來可用槽位：轉入方進入課程期後重新選槽
Step 7.  Flex Message 通知轉出/轉入雙方
```
