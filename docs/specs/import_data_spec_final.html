本系統匯入資料規格 — 家長／學員／報名課程流程（目標表 + 欄位型態）

本文件定義「任何外部來源的資料要匯入本系統 PostgreSQL 時，應對照的目標表結構、欄位型別與約束」。立場與資料來源無關：無論來源是 CSV、JSON、試算表、舊系統匯出檔或他系統 API，只要把資料整理成符合本規格的形狀，即可寫入本系統。型別與約束以實際 bootstrap schema（server/bootstrap/coreSchema.js、server/bootstrap/admin.js、db/migrations/002_admin_tables.sql）為準。

全系統最大的兩個語意陷阱：雙帳本（admin_enrollments 簡化訂單鏈 vs course_periods 正式期別鏈，兩邊 total_sessions 必須一致）與已用堂數計算（used_sessions 為死欄位，實際已用堂數一律以 checkin_records 的 COUNT 為準）。匯入前務必讀完第〇章。

0.3 資料型態與格式總約定（CSV / JSON 表示法）

  • UUID：留空時由資料庫 gen_random_uuid() 自動產生，匯入可不填 id。要外部指定請給合法 UUID 字串。
  • DATE：一律西元 YYYY-MM-DD（例：2026-06-26）。非西元曆需在匯入前自行換算為西元。
  • TIMESTAMPTZ：ISO 8601，含時區（例：2026-06-26T09:30:00+08:00 或 ...Z）。留空且有 DEFAULT NOW() 者可省。
  • BOOLEAN：true / false（CSV 可用 t/f、1/0，PostgreSQL 接受）。
  • INTEGER / DECIMAL(p,s)：純數字，金額用 DECIMAL(10,2)（兩位小數）。
  • ENUM：只能填「允許值」清單內的字串，大小寫須完全相符，否則寫入失敗或語意錯。
  • TEXT[]（陣列）：
  • PostgreSQL 字面值：{張小明,張小美}（含逗號／空白的元素用雙引號包：{"王 小明","李,小華"}）。
  • JSON 來源：用 JSON 陣列 ["張小明","張小美"]，由匯入程式轉成 array literal。
  • 空陣列：{}。
  • UUID[]：同陣列規則，元素為合法 UUID，空陣列 {}。
  • JSONB：合法 JSON 物件／陣列字串（例：{}、[]、{"mode":"team"}）。
  • 電話：09xxxxxxxx（10 碼，去空白／連字號、全形轉半形、國碼 +886 前置改 0）。
  • 身分證／證號：^[A-Z][0-9]{9}$，英文字母大寫。
  • 匯款末 5 碼：^\d{5}$。
  • 發票號碼：^[A-Z]{2}\d{8}$。
  • 場館代碼 venue_id：對應 venues.id（如 B/C/X），最長 10 字元。
  • 課程型別 course_type：整數 1–6（對應「1 對 1」至「1 對 6」），須先存在於 course_type_configs。

0.4 匯入關鍵注意（必讀）

  • 雙帳本 total_sessions 須一致：同一筆購買同時存在 admin_enrollments.total_sessions（帳本 A）與 course_periods.total_sessions（帳本 B＝對外真相），匯入時兩者數值必須相等，否則各前端頁面顯示打架。
  • used_sessions 為死欄位：course_periods.used_sessions 與 admin_enrollments.used_sessions 兩套計數器，選槽／簽到都不會 +1。前端「已用／剩餘」一律以 checkin_records 的 COUNT 計算。要呈現歷史已上堂數，必須補對應的 checkin_records 列，光填 used_sessions 不會顯示。
  • 到期只在 course_periods.expires_at（DATE NOT NULL）；admin_enrollments 沒有到期欄。匯入務必帶真實到期日，勿用「今天 +365 天」之類預設值讓已過期方案復活。
  • admin_enrollments 建議補外部單號欄：PK id 為內部編號（如 CP####），非自然鍵；無法對應來源系統的報名單號。要支援可重跑匯入（冪等），建議 ALTER TABLE admin_enrollments ADD COLUMN external_order_no TEXT 並建唯一索引，以來源報名單號當冪等鍵，避免重跑撞 PK 或重複建單。
  • students 無 primary_venue_id：學員表沒有「主場館」欄位，來源若帶學員館別，本系統無處可存（缺口）。
  • 緊急聯絡人無對應表：本系統目前無 emergency_contacts 表。要匯入緊急聯絡人（姓名／電話／關係），需先新建該表，否則無法落地。
  • 報名鏈「核准」不直接建期別：團報核准只建 admin_enrollments(pending_payment)；真正落地 course_periods + course_period_enrollments 發生在對帳階段，且需「該期全體成員付款皆確認」+「團有 coach_id」。歷史資料匯入時須自行把期別與名冊一併備齊。
  • 學員唯一性靠應用層：students.id_number 僅普通索引（非 DB UNIQUE），跨家長唯一與 (parent_id, id_number) 比對皆由匯入程式 SELECT-then-insert 控制，高併發下可能重複插入。

前置依賴（須先存在，非本流程建立）

報名計價與驗證讀取以下三表，匯入報名鏈前必須先備妥：

  • coaches（UUID PK）：冪等鍵 ragic_employee_id（VARCHAR(50) NOT NULL UNIQUE，可重用為任意來源員工編號；欄名為歷史遺留，與特定來源系統無綁定）；關鍵欄 pricing_multiplier(DECIMAL(5,2) NOT NULL DEFAULT 1.00；範圍 1.00–1.50 為業務慣例，無 DB CHECK)、is_senior(BOOLEAN NOT NULL DEFAULT FALSE)、name(VARCHAR(100) NOT NULL)、phone(VARCHAR(20) NOT NULL UNIQUE)、line_uid(VARCHAR(100) UNIQUE)、is_active(BOOLEAN NOT NULL DEFAULT TRUE)。報名計價教練係數與 course_periods.coach_id 來源。場館關聯經 coach_venues（複合 PK coach_id+venue_id）。
  • venues（VARCHAR(10) PK ＝ 場館代碼）：name(VARCHAR(100) NOT NULL)、full_name(VARCHAR(200))、full_address(TEXT)、銀行欄(bank_institution_name/bank_branch_name/account_holder/account_number)、is_active(BOOLEAN NOT NULL DEFAULT TRUE)。場館外鍵主鍵與金流收款。
  • course_type_configs（INTEGER PK，型別 1–6）：base_price(DECIMAL(10,2) NOT NULL DEFAULT 0，每期每人基準價，價格唯一來源)、max_students(INTEGER NOT NULL)、min_students(INTEGER NOT NULL DEFAULT 1，團報人數界限)、label(TEXT NOT NULL)、pending_changes(JSONB，排程價)、scheduled_effective_date(TIMESTAMPTZ，排程生效時間)、effective_date(DATE)。報名金額與團報人數驗證皆讀此表。
  • 另有 promotion_usages（優惠使用紀錄，含 admin_enrollment_id 回連，報名下單時條件 INSERT）。
